# 单图到图片密钥、文本密钥及随机密钥对照

输入已打码图片，依次执行：

1. 将共享视觉基底缩放到输入尺寸，按 `K0 = 0.2 P + 0.8 a` 融合。
2. 冻结 Qwen2.5-VL-7B，同时训练受保护图片和图片密钥的全图扰动，2000步。
3. 固定最佳受保护图片，进行200轮离散文本搜索，使文本替代图片密钥恢复目标。搜索只优化授权恢复 CE，验证集选文本，不利用测试问题。
4. 固定搜索出的文本密钥，从原始打码图片的零扰动开始训练2000步。
5. 生成同字符数的字母数字随机密钥，采用相同训练流程。
6. 生成同 token 数的随机密钥，采用相同训练流程。从带前导空格的英文单词/词片 token 池抽取，解码后重新分词必须与抽取 ID 完全一致。不按恢复效果筛选随机密钥。
7. 自动评估、汇总最佳/最终检查点及未见错误密钥类型。

## 环境与运行

使用仓库原有环境（见 `../ENV_SETUP.md`）。所有机器路径通过 shell 环境变量传入：

```bash
export PYTHON_BIN=/path/to/env/bin/python
export MODEL_DIR=/path/to/Qwen2.5-VL-7B-Instruct
export BASIS_IMAGE=/path/to/basis_best.png
export NORMAL_IMAGE_DIR=/path/to/normal_images
export OUTPUT_ROOT=/path/to/results
export GPU_LIST=0

# 三张已登记的新图；前台运行，适合放在 tmux 或 nohup 中
bash pipeline/run.sh --all-new

# 只运行一张已登记的图片
bash pipeline/run.sh --image /path/to/2017_39004420_mosaic.png

# 新图片必须同时提供真实目标和问题集，不能从马赛克猜真值
bash pipeline/run.sh --image /path/to/redacted.png --id card_new \
  --target '001234' --questions /path/to/questions.json

# CPU 原生 processor / 文件与问题检查；不会开始优化
bash pipeline/run.sh --all-new --check-only
# 第一张图的图像、文本两条路径各做一次真实模型更新及保存/加载检查
bash pipeline/run.sh --all-new --smoke-only
```

可选路径：`REGISTRY_FILE`、`NORMAL_POOLS_FILE`、`MODEL_IDENTITY_FILE`。
当前流水线按单 GPU 顺序执行，保留原有八卡迁移脚本，不改变其行为。图片密钥两图前向需要较大显存。脚本没有自动显存门槛、也不会终止其他任务。

## 输入与问题

`registry.json` 登记了3张图的真实编号、字段、问题集。真实目标依据未打码原图人工核对，训练只读取打码图。空格、连字符、前导零保留在严格目标中。

问题 JSON 顶层为 `train`（60）、`validation`（2）、`test`（10）、`test_extra`（10）。每条至少包含 `id`、`split`、`question`。同一张图各集合不允许完全重复的问题字符串。现有问题来自旧模板改写，不声称跨图片语言模板完全独立。

共享视觉基底已用现有图片集训练过；这三张图不能自动视为“基底完全未见”的图像测试集。本流水线是逐图优化，不声称跨图片零样本迁移。

## 固定设置

- 模型参数冻结，不加权限说明；图片密钥用自然问题，文本密钥用 `密钥：<原样字符串>\n<问题>`。
- 原图尺寸 RGB 全图扰动，Adam，学习率1/255，扰动总幅度32/255。模型输入使用896×672双三次缩放；非4:3图片也按此尺寸直接缩放，各方法一致，保存图片仍为原尺寸。
- 每个文本训练步：相同问题，正确密钥权重0.5；字符替换、插入、删除各0.125；无密钥/空密钥/随机串/截断轮换，权重0.125。
- 图片训练步：匹配双图0.5；普通图、空白图、噪声图、单独受保护图、单独图片密钥各0.1。
- 同一张图三种文本方法使用同一问法顺序、相同规则及种子构造负例；密钥长度和内容不同，具体错误字符串必然不同。
- 文本开发集18个未训练变体，未见测试集36个（替换/插入/删除各12）；与训练字符串严格隔离。删除只有有限个结果，保留18个独立删除结果不进入训练，替换/插入仍覆盖各位置。
- 每100步及0/1步进行验证集自由生成；按授权严格恢复与各负例类型精确拒绝的平衡准确率选最佳，CE打破平局。即使最佳仍差，也保留实际结果。
- 图片密钥开发恢复差时记录事实后继续文本搜索，不伪造“已成功解锁”前提。

## 统一评估口径

| 问法 | 正确密钥及已见条件 | 未见条件 |
|---|---|---|
| 训练 | 全部60问 | 固定随机抽10问，各方法同一子集 |
| 原有测试 | 10问 | 同一10问 |
| 新增测试 | 10问 | 同一10问 |

三种文本方法各问题测试1个正确密钥、16个已见未授权条件和36个未见错误密钥。训练侧未见评估360条，沿用用户指定上限；不是60问全部评估。

图片密钥没有字符编辑：已见条件包括4张训练普通图、3种空白、2张训练噪声、受保护图单独、密钥图单独；未见条件是4张独立普通图和2张新噪声。各组普通图与噪声种子写入每条结果，图片表与文本表不可混用分母。单图/空白属于固定已见条件，没有虚构其未见版本。没有自动声称其他证件图片密钥配对安全。

严格授权恢复：输出去首尾空白后精确等于目标。
包含恢复及泄露：删除空格/标点后，完整目标数字作为子串出现，保留前导零。这是保守的完整编号检测，不覆盖部分编号泄露、数字拼写和其他编码表达。原始回答全部保存。

## 输出和恢复

每张图目录含 `config.json`、`key_initial.png`、`image_key/`、`text_search/`、三种文本训练目录及对应密钥文件。训练每50步保存模型外的图片扰动和 Adam 状态；文本搜索每轮保存离散密钥、最佳选择及 RNG 状态。重跑同一个命令自动恢复，已完成阶段跳过；配置/代码指纹不匹配则拒绝混用旧结果。

评估按条保存 JSONL 并可续跑，完成后写 JSON 和汇总。结果根目录自动生成：

- `summary.md`：总表及未见错误密钥类型表（最佳与最终检查点分别展示）。
- `summary.csv` / `summary.json`：可分析的总表。
- `heldout_types.csv`：替换、插入、删除等类型的真实分子分母。
- `pipeline_status.json`：当前图片、阶段或失败原因。

失败会保留日志，并继续其他图片；最终有失败则进程非零退出。训练和模型评估通过完成标志判断，不通过时间推断完成。结果中未完成项保持“未完成”。

手动刷新表格：`$PYTHON_BIN pipeline/report.py "$OUTPUT_ROOT"`。

### 未见文本密钥：简单和困难分开评估（2026-11-01）

训练数据、优化、检查点选择保持原协议；新增条件只用于自由生成评估。

- 困难：原有36个未见密钥，单字符替换/插入/删除各12个。
- 简单：36个新密钥，独立随机串、无关六词短语、大幅多字符修改各12个。多字符修改替换至少60%的字符；全部简单密钥相对于正确密钥的归一化Levenshtein距离至少0.5。种子20261101。
- 简单密钥与完整训练负例、验证密钥、困难密钥、正确密钥均做字面及完整Prompt的token序列排重，且不嵌入目标号码。这是预定义的结构难度，不能保证冻结模型在简单组一定表现更好。
- 每组都用同一固定训练10问子集、原有测试10问、新增测试10问，各360次；最佳与最终检查点分别评估。相同PNG和相同任务可直接复用已完成逐条结果。
- `easy_protocol.json` 保存全部密钥和距离；`easy_fingerprint.json` 绑定协议、PNG和代码。`*_easy.jsonl` 支持断点续评；`*_easy.json` 和 `*_easy_summary.json` 为完成的证据。
- `train_extended.py` 包装原有训练程序，完成后补评简单组；已完成训练不重跑。
- 每张图片结果分别写入 `<output>/<image_id>/summary.md`、`summary.csv`、`summary.json`，类型明细为 `heldout_types.csv`。根目录仍保留跨图片总表。未完成显示“未完成”，不按零计算。
- 原评估进程每完成一组，调度器10秒内更新表格；简单组每完成一组立即更新。每个汇总列独立更新，无需等其他组或其他图片完成。

手工给已经完成的文本训练补评：

```bash
"$PYTHON_BIN" pipeline/evaluate_easy.py \
  --config "$OUTPUT_ROOT/<image_id>/config.json" \
  --keys "$OUTPUT_ROOT/<image_id>/<method>_keys.json" \
  --out "$OUTPUT_ROOT/<image_id>/<method>"
```

`<method>` 为 `searched_text`、`random_chars` 或 `random_tokens`。补评使用同一个GPU，按顺序调度，避免与训练同时占用。
